Regression answers one question: **what number comes next?**

Given this apartment's size, what should the rent be? Given how much we spent on ads, how many clicks will we get? Given a student's study hours, what's their test score?

You have data points. You want to draw a line through them. That line *is* your model.

## The simplest version

You have data about apartment sizes and their monthly rent:

| Size (m²) | Rent (€) |
|-----------|---------|
| 30 | 600 |
| 50 | 900 |
| 70 | 1200 |
| 90 | 1500 |

Plot these on a chart and you'll see they roughly form a line. If you can find that line's equation, you can predict the rent for *any* size — even sizes you've never seen.

The line's equation is one you know from school:

**y = mx + b**

- **m** = the slope (how much rent goes up per square meter)
- **b** = the intercept (the base rent even for 0 m²)
- **x** = the input (apartment size)
- **y** = the prediction (rent)

For our data, it's roughly: `rent = 15 × size + 150`. A 60m² apartment? About €1,050.

That equation *is* the model. Two numbers — slope and intercept — and you can predict anything.

## How does it learn?

The "learning" part is just finding the best m and b. Here's how:

1. **Start with random values.** Say m = 0, b = 0. Your line is flat at zero. Terrible predictions.

2. **Measure how wrong you are.** For each data point, check how far your prediction is from the real answer. Square those distances and average them. This number is called the **loss** — it tells you how bad your model is.

3. **Adjust m and b to make the loss smaller.** If predictions are too low, increase m. If too high, decrease it. Take small steps.

4. **Repeat** until the loss stops getting smaller.

<WebDevAnalogy webDev="A/B testing with analytics" ai="Gradient descent">
You already do this. In A/B testing, you try different versions and keep the one that performs best. Gradient descent is the same idea: try different values for m and b, measure which direction improves things, and keep going that way.
</WebDevAnalogy>

## The loss function

The loss function is just "how wrong am I, on average?" The most common one is **Mean Squared Error**:

<CodeBlock language="python" title="Loss = average squared error">
{`# For each data point:
error = predicted - actual     # how far off
squared = error ** 2           # make it positive, penalize big errors
loss = average of all squared  # one number: how bad is the model?`}
</CodeBlock>

Why squared? Two reasons. First, it makes negative errors positive (otherwise they'd cancel out). Second, it punishes big mistakes more than small ones — being off by 100 is way worse than being off by 10, and squaring captures that.

## Gradient descent in plain English

"Gradient descent" sounds fancy but it's dead simple. Imagine you're blindfolded on a hill and you want to find the lowest point:

1. Feel the ground around you — which direction goes downhill?
2. Take a small step that way
3. Repeat until you stop going lower

That's it. The "gradient" is just the slope of the ground (which direction is downhill). "Descent" means you're going down. You're walking downhill with small steps until you reach the bottom.

The **learning rate** is your step size. Too big and you overshoot the bottom. Too small and it takes forever. Typically something like 0.01.

<Callout type="info" title="This is the core of all ML training">
Gradient descent isn't just for regression. It's how neural networks learn, how LLMs are trained, how image generators improve. The idea scales up from 2 parameters to billions. Same concept, bigger hill.
</Callout>

## The code

Here's linear regression in scikit-learn. It's almost boring how simple it is:

<CodeBlock language="python" title="Complete linear regression">
{`from sklearn.linear_model import LinearRegression
import numpy as np

# Training data
sizes = np.array([[30], [50], [70], [90]])
rents = np.array([600, 900, 1200, 1500])

# Train
model = LinearRegression()
model.fit(sizes, rents)

# What did it learn?
print(f"Slope: {model.coef_[0]:.1f}")       # ~15.0
print(f"Intercept: {model.intercept_:.1f}")  # ~150.0

# Predict
print(model.predict([[60]]))  # ~1050.0`}
</CodeBlock>

Two lines to train, one line to predict. The library handles the gradient descent for you.

## Multiple features

Real models rarely use just one input. An apartment's rent depends on size, number of rooms, floor, distance to center, age of building...

The equation just gets more terms: `y = m1×size + m2×rooms + m3×floor + ... + b`

Same idea, more slopes. The model finds the best value for each one.

<CodeBlock language="python" title="Multiple features">
{`# Now each apartment has multiple features
apartments = [
    [30, 1, 3, 2.0],   # size, rooms, floor, km_to_center
    [50, 2, 5, 1.5],
    [70, 3, 2, 3.0],
    [90, 4, 8, 0.5],
]

model = LinearRegression()
model.fit(apartments, rents)

# Predict rent for a new apartment
model.predict([[60, 2, 4, 1.0]])  # considers all features`}
</CodeBlock>

## Summary

Regression predicts a number by drawing a line (or surface) through your data. Training means finding the parameters that minimize prediction error. Gradient descent does this by repeatedly taking small steps downhill. This same optimization loop — predict, measure error, adjust — is the foundation of everything in the next chapters.
